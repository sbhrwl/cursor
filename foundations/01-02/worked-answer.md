# Worked answer — Choose the first investigation

| Observation | First investigation | Concrete next check | Limit of the current evidence |
|---|---|---|---|
| `node: command not found` | Runtime | Inspect `command -v node` and the terminal's configured PATH/runtime installation. | The test has not begun; this is not a failed assertion. |
| Manager-only requirement was never supplied | Context | Recover the requirement and inspect the context/rules available to the task. | Correct execution of an incomplete request does not meet the missing requirement. |
| Edit refused by the tool boundary | Tools | Inspect the requested path/action and the configured permitted scope; use an allowed route or the appropriate approval process. | A refused request does not establish that a file was edited. |
| One test is treated as proof of all features | Model/inference, with context also worth reviewing | Build a requirement-to-evidence table and challenge unsupported conclusions. | A reasoning error does not prove the selected model is the only contributing cause. |

For the wrong-port demonstration, compare the attempted address with the service's configured listening address. The successful request to the corrected port supports that endpoint's observed response on that run. It does not verify the future approval feature.
